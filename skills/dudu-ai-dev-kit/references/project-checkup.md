# 项目体检（全面检查）

## 触发条件

用户说以下任一说法时，进入体检模式：
- "全面检查"
- "体检一下"
- "了解一下项目"
- "项目现在什么状态"
- "看看还有什么问题"

## 核心规则：只看不改！

**体检全程只读，绝对不对任何文件做修改。**

- ❌ 不要改代码
- ❌ 不要改配置
- ❌ 不要提交 git
- ✅ 只读文件、只跑检查命令、只输出报告

## 体检流程

### 第一步：摸清楚项目结构
1. 列出根目录所有文件和目录
2. 遍历核心代码目录（`spritesheet/` 或类似包名目录）
3. 每个主要文件读一遍，搞清楚它是干什么的
4. 画一张整体架构图（文字版）：哪些模块、模块之间什么关系

### 第二步：跑三件套检查
1. 编译检查：`.venv\Scripts\python.exe -m compileall -q`
2. pyflakes 静态检查：`.venv\Scripts\python.exe -m pyflakes`
3. 冒烟测试：offscreen 模式跑 `smoke_test.py`

### 第三步：Git 状态检查
1. 当前分支、最新提交、工作区是否干净
2. 和远程对比：有没有未推送的提交
3. 最近 10 次提交都是什么

### 第四步：输出体检报告

报告格式：

```
=== 项目体检报告 ===

1. 项目概览
   - 项目名：XXX
   - 版本：vX.Y.Z
   - 代码规模：XXXX 行 / XX 个文件
   - 技术栈：Python 3.11 + PyQt6

2. 目录结构
   - 包名/：核心代码
     - xxx.py：做什么的
     - yyy.py：做什么的
   - tools/：验证脚本
   - ...

3. 检查结果
   - 编译：✅ 通过 / ❌ 失败
   - pyflakes：✅ 无问题 / ⚠️ 有 N 个警告
   - 冒烟测试：✅ 18/18 / ❌ X/Y
   - Git：✅ 干净 / ⚠️ 有未提交改动

4. 发现的问题
   - 问题 1：...
   - 问题 2：...

5. 可优化点
   - 优化点 1：...
   - 优化点 2：...

=== 体检完成 ===
```

## 注意事项

- 体检报告要客观，不要隐瞒问题
- 不要在体检过程中擅自修复问题，只列出来
- 用户说"开始改"的时候，再从报告里挑问题逐个修复
- 体检完等用户指示下一步做什么
